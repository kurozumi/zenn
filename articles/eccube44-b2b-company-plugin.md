BtoB のサイトで買うのは会社です。卸価格も、支払方法も、締めも会社ごとに決まっていて、実際に画面を触る担当者は何人もいる。ところが EC-CUBE の会員は、どこまでいっても1人1アカウントです。

会社ごとに1アカウントを配ると、パスワードが社内で共有されて誰が発注したのか分からなくなります。担当者ごとにアカウントを作ると、今度は卸価格の会員グループを1人ずつ当てる作業が発生して、当て忘れた人だけ定価で買うことになる。

この隙間を埋めるために、取引先アカウント管理プラグインを作りました。会員に親子関係を持たせて、親を会社（取引先）、子を担当者として扱います。取引先に会員グループを当てておけば、担当者にも同じ条件が引き継がれます。**会社で決めた価格や配送方法が、発注する人によって変わりません。**

この記事では、何ができるプラグインなのかを紹介します。

## できること

| 機能 | 内容 |
| --- | --- |
| 取引先と担当者 | 会員に親子関係を持たせ、会社単位で扱う |
| 会社情報の引き継ぎ | 会社名・住所と会員グループを担当者へ引き継ぐ |
| 担当者の制限 | 退会、お届け先の登録、会社情報の編集を止める |
| 取引先による担当者発行 | 取引先の管理者が自分で担当者を作れる |
| 会社単位の注文履歴 | 取引先の管理者が担当者の注文も見られる |
| 連鎖退会 | 取引先が退会すると担当者もまとめて退会する |

新しく「会社」というテーブルを作ってはいません。会員テーブルに親会員への参照を1本足しただけです。親を持たない会員が取引先の管理者、親を持つ会員がその担当者。会社という箱を作らなかったのは、価格の根拠が会員グループと会社の2つになるのを避けたかったからです。

おかげで、既存の会員検索も会員CSVも他プラグインの会員拡張も、そのまま生きます。

## 管理画面でできること

### 取引先一覧

会員管理の下に「取引先一覧」が増えます。取引先として登録した会員が並び、担当者の数もここで見えます。担当者が0人の取引先にも「担当者を発行」がそのまま出ます。

### 取引先を登録する

会社名、代表者、住所、連絡先、会員グループを1画面で入れます。郵便番号を入れると住所が自動で入ります（本体の会員編集と同じ YubinBango を使っているので、`yubinbango.github.io` への通信を塞いでいる環境では働きません）。

会員グループはここで当ててください。卸価格は会員グループで決まるので、当てないまま担当者を発行すると担当者にも定価が出ます。このとき困るのは取引先で、店側は気づきません。

### すでにいる会員を取引先にする

会員編集の「取引先として扱う」を入れると、その会員が取引先になります。個人で買っていた相手が法人契約に切り替わったときに、登録し直さずに済みます。

ここで一点だけ引っかかりやすいところがあります。**会社名を入れただけでは取引先になりません。** 本体の会員登録にも会社名の欄があるので、勤務先を書いただけの会員と区別が付かないからです。会社名を入れて保存したのに取引先にならなかったときは、管理画面がその旨を出します。

取引先として動き出すのは、次のいずれかです。

- 取引先一覧の「取引先を登録」から作る
- 会員編集の「取引先として扱う」を入れる（会社名も必要）
- 担当者を1人発行する

### 担当者を発行する

取引先を開いて「担当者を発行」を押し、氏名とメールアドレスとパスワードを入れるだけです。会社名や住所は聞きません。取引先のものを引き継ぐので。

すでにいる会員を担当者にすることもできます。個人で買っていた人を、アカウントを作り直さずに過去の受注履歴ごと会社へ移せます。候補に出るのは会社名を持たない個人の会員だけで、取引先や他社の担当者、仮会員は出しません。所属先と食い違う会社名を持ったまま担当者になるのを避けるためです。

とはいえ、関係の無い会員を選べば事故になります。その会員の注文履歴が取引先の管理者に見えて、請求先も変わり、取引先の退会に連鎖して退会します。確認ダイアログで相手の氏名とメールアドレスを読み上げるので、そこで必ず確かめてください。

### 会員一覧の印と絞り込み

会員一覧の氏名の横に「取引先」「担当者（会社名）」が出ます。一覧を見ただけで、その会員がどういう立場か分かります。

詳細検索の「取引先区分」で、一般会員と取引先と担当者を絞り込めます。印だけだと目で探すことになるので、取引先が増えてくると担当者だけ抜き出す、といった操作ができません。

取引先一覧も、会員一覧の印も、マイページの出し分けも、全部同じ判定を使っています。一覧に出ているのに印が付かない、という食い違いは起きません。

### 受注一覧と受注詳細

その受注がどの取引先のものかを表示します。担当者の受注でも会社名で追えます。受注検索の会社名でも引けます。

出しているのは**受注した時点の取引先**です。担当者の所属はあとから変えられるので、いまの所属をたどると過去の受注まで移籍先のものとして表示されて、移った先の管理者に前の会社での注文履歴まで見えてしまいます。

取引先名は受注CSVと配送CSVの項目としても登録されます。既定は出力しない側なので、既存のCSVの列は増えません。出したいときは設定のCSV出力項目設定で「出力する」側へ移してください。

## 取引先が自分でできること

### 担当者アカウント

取引先の管理者がマイページにログインすると「担当者アカウント」が出ます。ここから担当者の追加と退会ができます。担当者と一般会員には、このメニューも画面も出しません。

初回の取引先開設は与信や契約の確認を伴うので店側、その後の担当者の増減は取引先自身、という分担を想定しています。店側で握りたい場合は基本設定で切れます。

乱発が気になるなら、取引先あたりの担当者数に上限を置けます。上限に達すると追加ボタンが消えます。

### 会社単位の注文履歴

管理者の注文履歴に、担当者の注文も並びます。誰の発注かが行ごとに出ます。一覧から注文詳細も開けますが、見える範囲は一覧と同じで他社の注文は開けません。

担当者には自分の注文だけを見せます。会社の中でも、発注の権限と閲覧の範囲は分けたい場面があるので。管理者にも自分の分だけ見せたい場合は、基本設定で切れます。

## 担当者にさせないこと

担当者には、既定で3つを止めています。

**会社情報の編集。** 担当者のマイページでは会社名と郵便番号と住所が編集できない状態になり、「会社の情報は取引先の管理者が管理しています。」と出ます。入力欄を JavaScript で有効にして送信しても、サーバー側で取引先の値に戻します。同じ画面の氏名や電話番号やメールアドレスは本人のものなので、これまでどおり変更できます。

**お届け先の登録。** 会社として登録した届け先だけを使わせる運用を想定しています。塞ぐのはマイページのお届け先一覧と、購入手続きの「お届け先を追加する」の両方です。ここは自分でも一度踏んだ穴で、マイページだけ塞いでも購入手続きから任意の住所を登録できてしまいました。

| 画面 | 担当者 | 取引先の管理者 |
| --- | --- | --- |
| マイページのお届け先一覧・登録 | 出ない | これまでどおり |
| 購入手続きの「お届け先を追加する」 | 出ない | これまでどおり |
| 購入手続きの「お届け先を変更」（選ぶだけ） | 出る | これまでどおり |
| 購入手続きの「削除」 | 出ない | これまでどおり |

代わりに、取引先が登録した届け先が担当者の購入手続きに並びます。支店や現場を取引先の側で登録しておけば、担当者はそこを選んで発注できます。会社が登録した届け先の間で商品を振り分けるのも、担当者にできます。

**退会手続き。** 担当者の増減は取引先の管理者が管理する建て付けなので、本人が自分で抜けられると管理の外で人が消えます。退会はアカウントを消さず状態を変えるだけなので、管理者からは「まだ居るのにログインできない担当者」に見えて原因が分かりません。

どれも基本設定で開けられます。現場へ直送する注文を担当者にも任せたい、といった運用なら開けてください。

そしてどれも、リンクを隠すだけでなく URL を直接開いても 403 になります。取引先の管理者と一般会員はこの制限を受けません。

## 退会と削除

取引先が退会すると、担当者も一緒に退会して、担当者のメールアドレスも解放されます。会社が取引をやめたのに担当者のアカウントだけ残ると、そのアカウントで発注できてしまうためです。

**管理画面で退会にしたときも連鎖します。** ここは作ってから直した部分で、最初はマイページの退会だけを拾っていました。法人の担当者がマイページから自分で退会することはまずなくて、取引終了は営業への連絡で起きて店側が管理画面で切り替えます。フロントだけ拾っていた頃は、設定を入れていても実際にはほとんど効いていませんでした。

メールアドレスの解放は本体と同じ形にしてあります。同じ人が別の会社の担当者として戻ってくることがあるので、解放しないとそのアドレスで二度と登録できません。

会員の削除は使えません。担当者がいる取引先を削除しようとすると「関連するデータがあるため削除できませんでした」で拒否されます。削除できてしまうと、残された担当者が会社名も会員グループも持ったまま親だけを失い、会社が存在しないのに卸価格で発注できる状態になるからです。運用は削除ではなく退会で回してください。

## 取引先に自分で申し込んでもらう

基本設定を入れると、法人専用の登録ページ（`/entry/company`）が開きます。通常の会員登録と入口が分かれて、会社名が必須になります。切っている間はページごと 404 を返すので、URL を知っていても開けません。

生年月日と性別と職業は聞きません。法人としての登録なので、担当者個人の属性は集めない作りにしています。

| | 通常の会員登録 | 取引先登録 |
| --- | --- | --- |
| URL | `/entry` | `/entry/company` |
| 会社名 | 任意 | 必須 |
| 会員グループ | 付かない | 「取引先登録で割り当てる」を入れたグループに入る |
| 登録後の扱い | 一般会員 | 取引先 |

既定で閉じてあるのは、取引先の開設に与信や契約の確認を伴う運用が多いからです。**このページを開いたまま審査を挟まないと、誰でも法人アカウントを作れます。** メール認証だけで本会員になるので、掛売りの設定次第では審査なしで発注できてしまいます。

審査を挟むなら、会員登録承認制プラグインを入れて、店舗設定で仮会員登録を有効にしてください。それだけです。会員グループの設定は要りません。取引先登録ページから来た会員は、それだけで審査の対象になります。承認制の仕組みをこのプラグインに持たせなかったのは、二重に審査が走るのを避けるためです。

審査が掛かるのは取引先登録ページから来た会員だけで、通常の会員登録はそのまま通ります。法人の申し込みには審査を挟んで、個人の会員登録は素通しにする、という分け方になります。

申し込みは仮会員で止まり、管理者宛てに承認依頼が届きます。取引先一覧では承認前の会社に「仮会員」が付くので、申し込みの溜まり具合がそのまま見えます。**承認するまで担当者は発行できません。** 担当者は本会員として作られるので、先に発行すると審査の前に発注できてしまいます。

## 卸価格との関係

価格は会員グループで決まります（会員グループ管理プラグインの機能です）。このプラグインは、取引先に付けた会員グループを担当者へ配ります。

配り方は「取引先のいまのグループに揃える」です。足すだけにすると、取引先をグループから外したときに担当者だけ卸価格のまま残ります。取引先の会員グループをあとから変えても、発行済みの担当者に自動で付きます。

担当者ごとに違う価格を当てたい場合は基本設定で切れますが、これは特殊な運用です。切ると、会社として卸価格で契約しているのに発注する人によって値段が変わる状態になりえます。

会員グループ管理プラグインは必須ではありません。入れていなくても単体で有効化できます。

| 機能 | 会員グループ管理あり | なし |
| --- | --- | --- |
| 親子関係、会社情報の固定、連鎖退会、担当者アカウント | ○ | ○ |
| 取引先を作るときの会員グループ割り当て | ○ | 項目が出ません |
| 担当者への会員グループの継承・同期 | ○ | 何もしません |
| 取引先の自己登録 | ○ | グループ無しで登録されます |

## 導入前に決めておくこと

設定の組み合わせで運用が変わるので、入れる前に決めておくと迷いません。

**誰が取引先を開設するか。** 店側が開設するのが既定です。与信や契約の確認が要る、取引先が限られている、という場合はこのまま。新規の引き合いが多いなら自己登録を開けて、承認制と組み合わせます。

**誰が担当者を登録するか。** 取引先に任せるのが既定です。取引先が10社程度までで担当者の入れ替わりも少ないなら、店側で全部登録する運用に切り替えられます。

**代表アカウントで発注させるか。** 取引先の代表アカウントは普通の会員なので、既定では発注できます。少人数の会社なら代表者自身も注文するはずなので、そのままで問題ありません。「代表は承認と請求だけ」という運用にしたい場合は、基本設定で代表の発注を止められます。止めるなら取引先に先に伝えてください。カートに入れてから止まると問い合わせになります。

## 導入時に一度だけやること

このプラグインを入れる前の受注には、取引先の控えがありません。控えの無い受注は現在の親をたどって拾いますが、そこには穴があります。担当者の所属を変えると過去の受注まで移った先の取引先のものになるし、会社を離れた担当者の在籍中の受注は元の会社から抜け落ちます。

埋めるコマンドを用意してあるので、導入直後に流してください。注文履歴の見え方と請求の集計の両方に効きます。

```bash
bin/console eccube:b2b-company:backfill-orders --dry-run   # 件数を確認
bin/console eccube:b2b-company:backfill-orders             # 実行
```

いまの所属で埋めるので、すでに所属を変えた担当者の過去の受注は変えたあとの取引先で固定されます。そこだけ注意してください。

## 差し替えられるところ

2つの処理を差し替えられます。インターフェースを実装したクラスを置くだけで効いて、`services.yaml` への追記は要りません。

**マイページで見せる受注の範囲。** 既定は「取引先の管理者には自社全体、それ以外は自分の受注だけ」です。部署単位で見せたい、役職者にだけ全体を見せたい、といった要望はここで足せます。ただし条件を足すことしかできません。既にある絞り込みは消せない作りにしてあります。差し替えた結果として他社の注文が見えると困るので。

**担当者を発行するときの初期値。** 与信の枠や独自の権限フラグを足せます。パスワードと秘密鍵は固定で入るようにしてあって、ここは外せません。外せると、ログインできないアカウントができます。

どちらも呼び出し口が1つにまとまっています。受注の範囲は注文履歴の一覧と注文詳細の両方に、担当者の初期値は管理画面とマイページの両方に、同じものが効きます。受注帳票プラグインを入れていれば、帳票のダウンロードにも同じ範囲が効きます。

画面の文言も、取引先登録と担当者アカウントまわりの3画面はコンテンツ管理のページ管理から編集できます。有効化のときにテーマへ写していて、既にあるファイルは上書きしません。裏を返すと、プラグインを更新しても編集済みのファイルは古いままです。既定へ戻したいときは、テーマ側のファイルを消してください。

## 動作要件

EC-CUBE 4.4 系、PHP 8.2 / 8.3 です。

```bash
composer require ec-cube/b2bcompany
bin/console eccube:plugin:install --code=B2BCompany
bin/console eccube:plugin:enable --code=B2BCompany
```

このプラグインは親子関係だけを持っていて、その上に載せるものは別に分けています。

- 発注承認アドオン：担当者の発注を承認待ちで止め、上長が承認してから店舗へ流します。承認限度額による多段の稟議にも対応します
- 月締め請求管理アドオン：取引先単位で受注をまとめて請求します。担当者3人がバラバラに発注しても、請求書は会社に1通です
- 会員登録承認制：取引先登録ページからの申し込みを仮会員で止め、管理者が承認するまで本会員にしません

順番としては、先にこのプラグインで取引先と担当者を整理してから、請求のアドオンを入れてください。逆順だと請求先が担当者ごとにバラけます。

「誰が誰の下にいるか」を1か所で持っておくと、その上に載る話がだいぶ楽になります。承認も締めも、結局は同じ親子関係を見ているだけなので。
