## 結論: 自作CSV機能を持つプラグインは、今のままだと脆弱性を抱え続けます

EC-CUBE 4.4(未リリース)で、CSVエクスポート/インポートに CSV数式インジェクション対策が入る予定です。ただしこの対策が効くのは、本体標準の `CsvExportService` / `CsvImportService` を使っている場合だけです。

もしプラグインが `fputcsv()` を直接呼ぶなどして独自にCSVを出力しているなら、本体がどれだけ対策しても、そのプラグインの脆弱性はそのまま残ります。

会員名や商品名の自由入力欄に `=HYPERLINK("http://example.com/","click")` のような文字列を仕込まれ、それがそのままCSVとしてエクスポートされ、担当者がExcelで開いてしまう――これがCSV数式インジェクションです。この記事では、EC-CUBE本体にマージ済みの実装(`CsvFormulaGuard`)を実際のソースから読み解きながら、プラグイン開発者は何をすべきかを整理します。

**TL;DR**
- EC-CUBE 4.4本体に `CsvFormulaGuard` によるCSV数式インジェクション対策が入る([PR #6871](https://github.com/EC-CUBE/ec-cube/pull/6871)、`4.4` ブランチにマージ済み)
- 対策が効くのは標準の `CsvExportService` / `CsvImportService` 経由のみ。独自CSV機能を持つプラグインは対象外
- 対応自体は難しくない。`Eccube\Util\CsvFormulaGuard::escape()` / `unescape()` をペアで呼べばよい
- **現時点(2026年7月)で EC-CUBE 4.4 は未リリース**。`Eccube\Util\CsvFormulaGuard` クラスは4.3系には存在しない

## この記事の位置づけ(重要)

前述の通り、この機能は EC-CUBE 本体リポジトリの [PR #6871](https://github.com/EC-CUBE/ec-cube/pull/6871) として実装され、**`4.4` ブランチにマージ済み**です。実際に `4.3` / `4.3.1` 系のブランチを確認しましたが、該当クラス(`CsvFormulaGuard`)も設定項目も存在せず、**4.3系では未対応**です。

つまりこの記事は「今すぐ使える機能」の解説ではなく、「次バージョンで入る予定の実装を先取りして読む」記事です。プラグイン開発者やカスタマイズ担当者が、リリース前に設計意図を掴んでおくことを目的としています。実際のリリース時には細部が変わる可能性がある点にご注意ください。

## 何を解決する機能か

CSV エクスポート機能を持つ Web アプリには「CSVインジェクション(Formula Injection)」と呼ばれる脆弱性クラスが存在します。

管理画面からエクスポートした CSV を、担当者が Excel やスプレッドシートで開く運用は珍しくありません。このとき、CSV のセルの中身が `=`, `+`, `-`, `@` などで始まっていると、Excel 側がそれを**数式として評価してしまう**ことがあります。

OWASP の解説([CSV Injection](https://owasp.org/www-community/attacks/CSV_Injection))によれば、危険とみなされる先頭文字は次の6種類です。

- `=`(等号)
- `+`(プラス)
- `-`(マイナス)
- `@`(アットマーク)
- タブ(`0x09`)
- 復帰(`0x0D`)

たとえば会員名や商品名の自由入力欄に `=HYPERLINK("http://example.com/","click")` のような文字列を仕込まれ、それがそのまま CSV エクスポートされて別の担当者が Excel で開いてしまうと、意図しないリンクや外部連携が実行される恐れがあります。OWASP はこの脆弱性の帰結として「スプレッドシートソフトの脆弱性を突いた乗っ取り」「警告を無視するユーザー心理の悪用」「シート内容の外部流出」を挙げています。

厄介なのは、**入力時ではなく出力(CSVエクスポート)時に評価される**受動的な脆弱性だという点です。フォームのバリデーションだけでは防げず、出力層での対策が必要になります。

## Symfony の CVE-2021-41270 と同じ方式

EC-CUBE の実装方針は PR 本文で明言されている通り、Symfony のセキュリティアドバイザリ [CVE-2021-41270](https://github.com/symfony/symfony/security/advisories/GHSA-2xhg-w2g5-w95x)(`symfony/serializer` の `CsvEncoder`)と同じ方式を採っています。

Symfony 側の経緯を実際のソース・修正コミットで確認すると、次のような変遷がありました。

- Symfony 4.1 で追加されたオプトイン機能 `csv_escape_formulas` は、`=` `+` `-` `@` で始まるセルの先頭に**タブ文字を付与**する方式でした。
- しかし OWASP が危険文字リストにタブ・復帰も追加したため、「タブを付与して回避したつもりが、そのタブ自体が新たな危険文字になる」という状態になり、この対策自体が不十分になりました。
- そこで Symfony は対象文字を `['=', '-', '+', '@', "\t", "\r"]` に拡張し、エスケープ方式を「タブ付与」から「**先頭にシングルクォート `'` を付与**」に変更しました(CVE-2021-41270、修正版は 4.4.35 / 5.3.12)。

Excel はセル先頭の `'` を「これはテキストとして扱ってください」という書式指定子として解釈し、表示時には取り除いた上で文字列として扱います。数式評価を回避しつつ、見た目上は元の値とほぼ変わらないという扱いやすさがあります。ただしこれは主に Excel の挙動で、Google スプレッドシートや LibreOffice Calc など別のソフトで開いた場合は `'` がそのまま可視文字として残ることがあります。数式評価を防ぐための緩和策であって、あらゆる表計算ソフトで「見た目まで完全に元通りになる」ことを保証するものではない点に注意してください。

EC-CUBE 4.4 の実装は、このトリガー文字集合(`= + - @` タブ 復帰)を Symfony と共通にした上で、EC-CUBE 特有の要件、つまり「**エクスポートしたCSVをそのままCSV取込機能で再取込する**」という往復利用に対応させるため、独自の拡張を加えています。

## 実装を読む: CsvFormulaGuard

対策の中心は新設された `Eccube\Util\CsvFormulaGuard` クラスです(`src/Eccube/Util/CsvFormulaGuard.php`)。`final class` として実装されており、`escape()` と `unescape()` という対になる静的メソッドを持ちます。

```php
final class CsvFormulaGuard
{
    private const FORMULA_TRIGGER = '/^[=+\-@\t\r]/';
    private const ESCAPED_PREFIX = "/^'[=+\\-@\\t\\r']/";

    public static function escape(int|string|null $value): int|string|null
    {
        if (!is_string($value) || $value === '') {
            return $value;
        }
        if (str_starts_with($value, "'") || preg_match(self::FORMULA_TRIGGER, $value)) {
            return "'".$value;
        }
        return $value;
    }

    public static function unescape(string $value): string
    {
        if (preg_match(self::ESCAPED_PREFIX, $value)) {
            return substr($value, 1);
        }
        return $value;
    }
}
```

ポイントは以下の3点です。

### 1. 既に `'` で始まる値も対象にする(二重化)

`escape()` は正規表現でトリガー文字にマッチする値だけでなく、**既に `'` で始まる値**も対象にして、もう一段 `'` を付与します。これにより「ユーザーが最初から `'07012345678`(電話番号の頭ゼロ落ち防止など)のような値を入力していたケース」でも、`unescape()` で1つだけ `'` を剥がせば元の値に正確に戻ります。

テストコード(`CsvFormulaGuardTest.php`)で確認できた実例です。

| 入力 | `escape()` 後 | `unescape()` 後 |
|---|---|---|
| `=SUM(A1:A2)` | `'=SUM(A1:A2)` | `=SUM(A1:A2)` |
| `+1+1` | `'+1+1` | `+1+1` |
| `@SUM(1)` | `'@SUM(1)` | `@SUM(1)` |
| `\tfoo`(タブ始まり) | `'\tfoo` | `\tfoo` |
| `'foo`(元から`'`始まり) | `''foo`(二重化) | `'foo`(1つだけ剥がす) |
| `foo` / `山田太郎` / `user@example.com` | 変更なし | 変更なし |

`user@example.com` のようにメールアドレス中に `@` が含まれていても、**先頭文字でなければ**トリガーにならない点も見て取れます(正規表現が `^` アンカー付きのため)。

### 2. Symfony にはない unescape を持つ

Symfony の `CsvEncoder` はエクスポート用途に特化しており、対応する `unescape` 処理を持ちません(調査時点のソースで確認)。一方 EC-CUBE の CSV 機能は「エクスポート → Excelで修正 → 同じ画面から再取込」という運用が一般的なため、対称的な `unescape()` を用意し、エクスポートで付与した `'` を取込時に自動で取り除く設計になっています。

### 3. 往復変換のテスト

`"'=1+1"`(ユーザーが最初から `'` 付きの数式っぽい文字列を入力していたケース)についても、`escape()` → `unescape()` を経て完全に元の値へ復元されることがテストで確認されています。単なる不可逆マスキングではなく、可逆な変換として設計されている点が Symfony の実装との違いです。

## どこに組み込まれているか

`CsvFormulaGuard` 単体では何も自動で動きません。実際に呼び出しているのは次の箇所です。

**エクスポート側 — `CsvExportService.php`**

コンストラクタに `BaseInfoRepository` が注入され、ヘッダ出力・データ出力それぞれの開始時に店舗設定のフラグを解決します。`fputcsv()` で行を書き出す直前に、設定が有効であれば各セルへ `CsvFormulaGuard::escape()` を適用します(ヘッダ行・データ行の両方に対称に適用)。

**取込側 — `CsvImportService.php`**

コンストラクタに第5引数として `bool $unescapeFormulas = true` が追加され、行を読み込むたびに有効であれば各セル(null を除く)へ `CsvFormulaGuard::unescape()` を適用します。

**呼び出し元 — `AbstractCsvImportController.php`**

`BaseInfoRepository` を `#[Required]` セッターDIで受け取り、`CsvImportService` のインスタンス生成時に店舗設定のフラグを渡すよう変更されています。

## 管理画面の設定項目

この機能は常時ONの固定仕様ではなく、**店舗設定からON/OFFを切り替えられる**設計です。

- エンティティ: `BaseInfo` に `option_sanitize_csv_formulas`(bool、デフォルト `true`)という新しいプロパティ・カラムが追加されています。
- フォーム: `ShopMasterType.php` に `option_sanitize_csv_formulas` フィールド(`ToggleSwitchType`)が追加されています。
- 画面: 管理画面の「設定 > 店舗設定 > 基本情報設定」に「CSV設定」というカードが新設され、トグルスイッチで切り替えられます。ツールチップには「CSV出力時に、表計算ソフトで数式評価され得る先頭文字を無害化します。CSV取込時の復元処理も同じ設定に連動するため、有効時に出力したCSVは有効なまま取り込んでください」といった趣旨の説明が入ります。

**注意点として、PRのテスト手順には「`bin/console doctrine:migrations:migrate` でカラムが追加されることを確認する」という記述がありますが、調査時点で該当のマイグレーションファイルが `app/DoctrineMigrations/` 配下に見当たりませんでした。**マージ直後のドラフト実装である可能性があるため、実際にリリースされる際は変更点に含まれているか確認することをおすすめします。

設定がエクスポートとインポートの両方に連動する点は運用上重要です。ツールチップにもある通り、「有効な状態で出力したCSVは、有効なまま取り込む」という前提が崩れると、`'` が残った状態でデータが保存されてしまう(あるいはその逆)という不整合が起こり得ます。

## プラグイン開発者への影響

ここからが実務上いちばん気になる部分だと思います。自作プラグインで独自の CSV 出力・取込機能を持っている場合、この変更にどう向き合えばよいでしょうか。

### 影響を受けるケース・受けないケース

- EC-CUBE 標準の `CsvExportService` / `CsvImportService`、あるいは `AbstractCsvImportController` を継承・利用してCSV機能を実装している場合は、**本体の変更がそのまま適用される**ため、プラグイン側で特別な対応は不要です。
- プラグインが独自に `fputcsv()` を直接呼んだり、独自のCSV生成ロジックを持っている場合は、**本体の対策の恩恵を受けません**。ユーザーの自由入力値をCSV出力する機能があるなら、同じ脆弱性がプラグイン側にも存在する可能性があります。

### 独自CSV機能がある場合の対応方針

`CsvFormulaGuard` は EC-CUBE 本体の `Eccube\Util` 名前空間に属するクラスであり、本体が読み込まれていれば当然プラグインからも利用可能です。独自実装を1から書くよりも、本体のクラスをそのまま使う方が挙動を統一でき、店舗側からすると「本体機能でも同じルールが適用されている」という一貫性も保てます。

**注意: このクラスは EC-CUBE 4.4 リリース前の環境には存在しません。** 4.3系を対象にプラグインを配布している場合、このコードをそのまま使うと `Class "Eccube\Util\CsvFormulaGuard" not found` で致命的エラーになります。`class_exists()` によるガードを入れるか、4.3系向けには同等のロジックを自前で実装したうえで、4.4がリリースされたタイミングで本体のクラスに切り替える、といった対応を検討してください。

```php
use Eccube\Util\CsvFormulaGuard;

if (!class_exists(CsvFormulaGuard::class)) {
    // EC-CUBE 4.4 未満の環境向けフォールバック実装、または処理をスキップ
}

// エクスポート時
$row = array_map(fn ($cell) => CsvFormulaGuard::escape($cell), $row);
fputcsv($fp, $row);

// 取込時
$row = array_map(fn ($cell) => $cell === null ? null : CsvFormulaGuard::unescape($cell), $row);
```

このとき気をつけたいのは次の2点です。

1. **店舗設定と連動させるかどうかを決める**。本体の設定(`BaseInfo::isOptionSanitizeCsvFormulas()`)をプラグイン側からも参照して連動させれば、店舗運営者から見た挙動の一貫性が保てます。逆にプラグインの性質上、常にONにしたい(あるいは店舗設定と無関係に独立させたい)場合は、その旨をプラグインの説明に明記しておくとよいでしょう。
2. **escape とunescapeは必ずペアで使う**。エクスポートだけ対策してインポート側で `unescape()` を呼ばないと、`'` が付与されたままデータベースに保存されてしまいます。往復を前提に設計されている機能なので、片側だけ導入すると事故のもとになります。

### 現時点でできる備え

4.4 はまだリリース前のため、今すぐプラグインを改修する必要はありません。ただし、独自のCSV出力機能を持つプラグインを開発・保守している場合は、リリースを待たずに「入力値の先頭文字を無害化する」という考え方自体は先取りして導入しておいて損はありません。攻撃としては既に知られているものであり、対策を後回しにする理由はないためです。

## まとめ

- EC-CUBE 4.4(未リリース)で、CSVエクスポート/インポートにおける数式インジェクション対策が入る予定です。
- 実装は Symfony の CVE-2021-41270 と同じトリガー文字・同じ「先頭に`'`を付与」方式を採用しつつ、往復変換(エクスポート→再取込)に対応するため、二重化を含む対称的な `escape()`/`unescape()` として独自に拡張されています。
- 店舗設定の「CSV設定」からON/OFFを切り替え可能(デフォルトON)。
- 独自CSV機能を持つプラグインは本体の対策の恩恵を受けないため、`Eccube\Util\CsvFormulaGuard` を利用した個別対応を検討する価値があります。

正式リリース時には実装が変わっている可能性があるため、最終的な仕様は公式のリリースノートや doc4.ec-cube.net でご確認ください。
